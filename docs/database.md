# Database

PostgreSQL 14+ with PostGIS (recommended) and `pg_trgm`. 29 tables; migrations are in `prisma/migrations`:

| Migration      | Purpose                                                                      |
| -------------- | ---------------------------------------------------------------------------- |
| `…_extensions` | `pg_trgm` for fuzzy business-name search                                     |
| `…_init`       | Tables, enums, FKs, btree/GIN indexes (generated by Prisma)                  |
| `…_postgis`    | Generated `location` geography column + GiST index (skipped without PostGIS) |
| `…_integrity`  | CHECK constraints, partial unique indexes, append-only triggers              |

## Domains

- **Identity**: `users`, `refresh_tokens` (rotation families), `otp_codes`, `device_tokens`
- **Artisans**: `artisan_profiles`, `categories`, `artisan_categories`, `availability_slots`, `portfolio_photos`, `identity_verifications`, `favorites`
- **Requests**: `service_requests`, `request_photos`, `request_events` (append-only), `quotes`, `messages`
- **Trust & safety**: `reviews`, `complaints`, `disputes`, `evidence_files`, `reports`, `trust_score_snapshots`
- **Notifications**: `notifications`, `notification_deliveries`, `notification_preferences`
- **Payments** (flagged off): `payments`, `webhook_events`
- **Platform**: `audit_logs` (append-only), `idempotency_keys`

## Delete rules

Users, requests, reviews, complaints, disputes and artisan profiles referenced by requests use `Restrict`: accounts are anonymised (`deletedAt`, `anonymizedAt`, PII nulled), never hard-deleted, so history that feeds trust scores survives. Rows that belong to a parent only for convenience (tokens, OTPs, devices, notifications, favourites, request photos, messages, quotes, evidence) cascade.

## Search indexes

| Query                                 | Index                                                  |
| ------------------------------------- | ------------------------------------------------------ |
| Radius search (PostGIS)               | `artisan_profiles_location_gist_idx` (GiST)            |
| Radius search (fallback bounding box) | `(status, lat, lng)`                                   |
| "Available now", best trust first     | `(status, isAvailableNow, trustScore DESC)`            |
| Category filter                       | `artisan_categories (categoryId, artisanId)`           |
| Name search `q=`                      | `artisan_profiles_businessName_trgm_idx` (GIN trigram) |
| Artisan inbox / customer list         | `service_requests (artisanId                           | customerId, status, createdAt DESC)` |
| Expiry job                            | `service_requests (status, expiresAt)`                 |
| Repeat-customer stats                 | `service_requests (artisanId, customerId)`             |

### EXPLAIN notes

On the 18-row demo dataset the planner (correctly) prefers the `(status, trustScore)` btree and filters with `ST_DWithin`; a table that small does not justify the GiST scan. To see the GiST index used, test on a larger table or force it:

```sql
SET enable_seqscan = off; SET enable_indexscan = off;  -- bitmap scan on the GiST index
EXPLAIN ANALYZE
SELECT id FROM artisan_profiles
WHERE status = 'ACTIVE'
  AND ST_DWithin(location, ST_SetSRID(ST_MakePoint(7.0231, 4.8277), 4326)::geography, 5000);
```

Phase 3 adds a load test (10k generated artisans) and records the real plans here.

## Conventions

Tables snake_case (`@@map`), columns camelCase: quote them in raw SQL (`"isAvailableNow"`). Money in kobo. All timestamps are UTC `timestamp(3)`.
